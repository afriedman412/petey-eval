# petey-eval

Evaluation harness for [petey](https://github.com/afriedman412/petey) — benchmarks
parser and LLM configurations against ground-truth datasets.

## Project structure

```
petey-eval/
├── BENCHMARK_PLAN.md          # Full benchmark matrix and rationale
├── eval_permutations.ipynb    # Main benchmark notebook — runs configs, scores, plots
├── evaluate_claude_data.py    # Scoring library (semantic similarity, per-field rubrics)
├── ground_truth.csv           # 12 synthetic ED note patients, 6 fields each
├── claude_data/               # 12 Claude-generated ED note PDFs + GT generator
│   ├── patient_01–12.pdf
│   ├── ground_truth.csv
│   └── evaluate.py
├── requirements.txt
└── Makefile                   # `make venv` / `make install`
```

## Datasets

### Medical (ED notes)
- 12 synthetic PDFs generated by Claude, clean embedded text
- Ground truth: `ground_truth.csv` — name, age, sex, complaint1, complaint2, outcome
- Schema: `EDNote` pydantic model in the notebook

### PAR (DHCR decisions)
- Real-world government PDFs, some scanned/degraded
- Ground truth: `selected_ground_truths.csv` (in petey repo) — manually verified ra_docket + issue_date
- Regex baseline: `parsed_pars.csv` (unverified, petey repo)

## How it works

1. **Config** = `(parser, model)` tuple
2. Each config runs `petey.extract_batch()` over the PDF set
3. Results scored against ground truth via `evaluate_claude_data.py`:
   - Semantic similarity (sentence-transformers `all-MiniLM-L6-v2`, TF-IDF fallback)
   - Per-field scorers: exact match for age/sex, token overlap for names, cosine for complaints/outcome
   - Thresholds: PASS >= 0.85, PARTIAL >= 0.60, FAIL < 0.60

## Benchmark plan

See [BENCHMARK_PLAN.md](BENCHMARK_PLAN.md) for the full matrix:
- 4 parsers × 1 model (parser sweep)
- 1 parser × 6 models (model sweep)

## Setup

```bash
make venv          # create venv + install deps
```

Requires petey installed (`pip install petey` or editable from ../petey).

## Auth

API keys needed depend on which configs you run. See the auth table in
[BENCHMARK_PLAN.md](BENCHMARK_PLAN.md#auth-requirements). At minimum:
- `OPENAI_API_KEY` for the default model
- `DATALAB_API_KEY` for Datalab parser
- `ANTHROPIC_API_KEY` / `GEMINI_API_KEY` for model sweep
- `GOOGLE_APPLICATION_CREDENTIALS=./gcp-sa.json` for Google Document AI / Vision
- AWS credentials for Textract
- `UNSTRUCTURED_API_KEY` as needed
